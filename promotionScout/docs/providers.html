Overview / Sites and feeds

Sites and feeds

Scout watches a catalog of sites and reads their RSS/Atom feeds. Each site turns a topic's search terms or tags into feed addresses, or offers one feed for every topic. No API keys are needed. The Sites tab of the web interface lists the catalog, and the Feeds tab (step 1) lists every concrete feed with its outcome.

Three kinds of sites

KindWhat Scout sendsExample address
SearchEach search term of a topic, typed or derived from the topic.https://hnrss.org/newest?q={query}
TagEach tag of a topic, written the way the site expects: joined (balconygarden), hyphenated (balcony-garden) or letters and digits only.https://dev.to/feed/tag/{tag}
FeedNothing; one feed is read for all topics and the model decides what is relevant.https://www.producthunt.com/feed

For a topic with search terms balcony garden and container tomatoes, Hacker News receives two feeds, one per term. Reddit receives one feed with (balcony garden) OR (container tomatoes), which keeps requests to Reddit low. When you leave search terms or tags empty, Scout derives them from the topic: AI gaming news searches for ai gaming and uses the tags ai gaming, ai and gaming. When two topics produce the same address, Scout reads it once.

The catalog lives in config/sites.json and is synchronized every time the agent starts. Disabling a built-in site is kept across restarts; built-in sites cannot be deleted. A tag a site does not know shows as skipped, not as an error.

Adding a site

In the Sites tab enter a name, choose the kind and give the address. A feed address can be the feed itself or a web page that advertises one; Scout fetches it once and keeps the feed URL. A page without a same-origin feed link is refused, and an address that redirects is refused with the target to use instead. Search and tag addresses contain {query} or {tag}. An address beginning with / is an RSSHub route, for example /telegram/channel/name or /threads/name; the RSSHub documentation lists the available routes. Feeds that follow one account, such as a YouTube channel (https://www.youtube.com/feeds/videos.xml?channel_id=…), a Substack publication or a GitHub repository's discussions, belong here as feed sites. Deleting a site you added keeps the entries it already collected.

What Scout reads

Scout reads RSS 2.0, RSS 1.0 and Atom. It stores each entry's title, link, author, date and the text the feed carries, after removing known boilerplate such as Hacker News point counts. Entries with neither title nor text, such as image-only posts, are skipped. Scout does not open linked articles or comments, render pages, log in or read private content. How much text an entry has depends on the site, and the model can compare only what the feed provides.

Request limits

Each feed is read at most once per hour, including after errors, and validators avoid downloading unchanged feeds. Requests to the same host are at least one second apart, or ten seconds for Reddit. A 429 is never retried. A 403 or 429 pauses the whole host for six hours; its feeds keep their turn and are read after the pause. Server errors are retried up to three times. Requests time out after 20 seconds and responses are limited to 5 MiB. Stop cancels the request in progress.

RSSHub

RSSHub is a separate native service, built by the agent's install step, that turns website routes into feeds. The agent daemon starts it when the agent starts, at http://127.0.0.1:1200 inside the container by default, starts it again if it stops and stops it when the agent stops. If it cannot start, only RSSHub feeds fail. RSSHub uses memory caching, so SQLite remains the only database. Some routes require credentials or a browser, which are not installed. The site and feed contract defines these rules.

A route is a small program written for one site: it calls the site's public API or reads its pages and returns the result as RSS. RSSHub can therefore produce feeds only for sites that have a route in the pinned version; it cannot guess how to read an unknown site. Built-in sites use it for Bluesky search and Hugging Face daily papers; every other built-in site has its own feed and is read directly. Because RSSHub does this work, Scout itself parses only RSS and Atom, but behind a route RSSHub may call APIs or scrape pages.

For a site without a route, first add its page: many sites advertise a feed (WordPress, Discourse, XenForo, Lemmy, Mastodon, Stack Exchange, YouTube, Substack). A newer RSSHub version may also add a route; the pinned version is set in config/services/install.json and installed again by the install step at the next agent start. RSSHub's generic transform route, which turns any HTML or JSON page into a feed through CSS selectors, stays disabled: it needs ALLOW_USER_SUPPLY_UNSAFE_DOMAIN, would let any process in the agent container make RSSHub fetch any address, breaks at every redesign and would turn page HTML into feeds that the site never offered.

Sites that were tested and left out

These candidates were tested live with one request each and are not in the catalog:

SiteReason
Quora, Unity Discussions, ResetEra, Linus Tech Tips forumAnswer automated requests with 403. Scout does not pretend to be a browser.
Tumblr, X/TwitterTheir RSSHub routes need API keys or a login.
Indie HackersNo official feed or API; the community aggregator answered 500 to every request.
DiscuitIts feed address returns an HTML page, not a feed.
Mbin (fedia.io, kbin.earth), HubskiNo working feed at the documented addresses (404 or 403).
DiggNo longer a community site; it now aggregates tech news automatically.
Fark, Stacker NewsFeeds carry only titles of 10 to 20 characters, too little for the model to compare.
Discord, Facebook GroupsNo public content; private groups are outside the product.

Topic-specific forums with working feeds, such as Tom's Hardware, Level1Techs or the Godot forum, were left out of the general catalog on purpose; add them as feed sites when your topics need them.
