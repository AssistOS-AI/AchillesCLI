## Introduction

The embedding interface lets topic ranking change local models without coupling the collection workflow to a runtime or vector dimension.

## Core Content

### Profiles and execution

`config/embedding-models.json` defines the default and named profiles. Profiles own provider, model repository, immutable revision, dimensions, pooling, dtype, token limit, query/document prefixes, the relevance threshold for topics and an optional `subtopicThreshold` for discussions, which defaults to the topic threshold. The default `embeddinggemma-300m` (`onnx-community/embeddinggemma-300m-ONNX`) uses q8 weights, the model's own `sentence_embedding` output (`sentence` pooling), normalized 768-dimensional vectors, a 2048-token limit, the query prefix `task: search result | query: `, the document prefix `title: none | text: `, threshold 0.25 and subtopic threshold 0.35. `multilingual-e5-small` uses mean pooling, 384 dimensions, a 512-token limit, E5 prefixes and threshold 0.80. `minilm-en` uses 384 dimensions, a 256-token limit without prefixes and an uncalibrated threshold of 0.75. The runtime uses two CPU threads. Full immutable SHAs reside in the catalog.

`src/embeddings/index.mjs` exposes the service and provider registry. A provider implements `create`, `embed` and `dispose` with a version identifying vector semantics. Any implementation change affecting vectors must change that version. The [embedding namespace](../wiki.html#definition-namespace) hashes provider version and all vector profile fields; the threshold is excluded, so recalibrating it reuses stored vectors. Cache keys also include text and query/document role. Changed models require explicit download and fresh evaluations; old vectors can remain stored under their own namespace.

The agent's [install step](../wiki.html#definition-install-step) permits model network access when local loading reports unavailable files. Every run remains offline for models. Inference opens the local model directory directly to avoid metadata lookup requests. Missing or corrupt model artifacts, incompatible runtime versions, invalid dimensions, nonfinite values and zero vectors are explicit failures. No keyword fallback, remote inference or invented vector is allowed.

### Process boundary

The default model repository must be `onnx-community/embeddinggemma-300m-ONNX` at its pinned revision. Its q8 weights take about 309 MB on disk, and inference measured about 1.6 GB of peak resident memory in the cycle process, compared with about 0.6 GB for `multilingual-e5-small`. EmbeddingGemma is distributed under the Gemma Terms of Use. Transformers.js 4.3.1 must run ONNX inference on the CPU in a worker thread (`src/embeddings/transformers-worker.mjs`) of the [cycle task](../wiki.html#definition-cycle-task) process, with two intra-operation threads and one inter-operation thread. One EmbeddingGemma document near the token limit takes about four seconds; on the main thread this blocked the event loop for the whole inference, so the worker keeps the cycle's Stop check, signals and request timeouts responsive during ranking. Errors cross the thread boundary with their code, and a worker that dies fails the run with `INFERENCE_FAILED`. No separate model server, port or HTTP inference call is involved. The install step loads the model from `models/` in the [data directory](../wiki.html#definition-data-directory) for one readiness embedding and releases it. Each [run](../wiki.html#definition-run) with active topics loads the model again and releases it when the run ends, so the model does not occupy memory between runs. SQLite caches survive the task; an unchanged vector can be reused without rerunning inference.

The query role must prepend the profile's query prefix and the document role its document prefix. The token limit includes prefixes and special tokens. Neither the MCP tools nor the web interface offer model selection; the internal alternate profile is not an automatic fallback.

### Ranking contracts

Cosine similarity compares normalized vectors. The internal embedding service rejects oversized inputs. Topic ranking tries each document, recursively splits overlong text by Unicode character count and keeps the maximum passage score and its original text as review context. This bounded-token approach can split sentences and lose cross-passage context. A topic query must fit the model limit and is never silently truncated. A run reports a topic that exceeds the limit as an error and ranks the remaining topics.

Topic ranking ranks only English or undecided entries (see the provider specification), filters by a fixed seven-day recent time window and selects scores at or above the active profile's threshold. Scores are model-dependent similarities, not probabilities or evidence that a discussion welcomes promotion, and thresholds are not comparable between models. The compared document is the entry title plus its feed text; several built-in sites (Hacker News, Lobsters, Product Hunt, Medium) supply little or no text, so their entries are effectively ranked by title.

The thresholds come from a calibration on 95 operator-labeled topic/post pairs (34 relevant) drawn at random from one live collection of 1,259 entries for five gaming and AI topics. `multilingual-e5-small` at the former 0.75 reached 37% precision and 100% recall; its scores for relevant and unrelated posts overlapped between 0.71 and 0.86, and its best threshold, 0.80, reached 56% precision and 88% recall. `embeddinggemma-300m` at 0.25 reached 69% precision and 74% recall, and 74% precision with the same recall once the English-only rule removed 7 non-English pairs, none labeled relevant. `bge-m3` and `Qwen3-Embedding-0.6B` did not exceed EmbeddingGemma; scoring each topic aspect separately helped only the smaller models and a cross-encoder reranker performed worse. With this sample, ranking-quality differences below about 0.05 AUC are not significant. Entries matching only one part of a compound topic, such as AI without games, remain the main source of false positives; an explicit topic description reduces them. Recalibration on representative labeled data is required before maintainers change a threshold. The MCP tools and web interface have no model or threshold switches. The interface reads scores for the current namespace and threshold only.

A score is the cosine similarity of two normalized vectors, between −1 and 1. It is neither a probability nor a fraction of a maximum: with EmbeddingGemma unrelated texts score near 0, relevant ones usually 0.3 to 0.65, and only near-identical texts approach 1, so documentation and the interface must not present scores as percentages. Topic matches and subtopic matches use the same measure with separate thresholds; the discussions specification records how the provisional subtopic threshold was chosen.

Each 768-dimensional float32 vector uses 3,072 payload bytes (384 dimensions: 1,536) before keys and SQLite overhead. Multiple models, roles and passages increase storage. The application performs a sequential scan and exact cosine comparison, with no vector index or additional database. Cached evaluations avoid repeated inference for unchanged records; very large collections require measurement and explicit retention policy outside this contract.
