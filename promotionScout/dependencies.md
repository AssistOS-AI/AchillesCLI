# Dependencies

## Feed parsing

`fast-xml-parser` 5.11.2, MIT, provides RSS/Atom XML validation and parsing. Node has no built-in XML parser; a handwritten XML parser would not safely handle namespaces, CDATA and malformed feeds. This project-local npm exception supports RSS 2.0, RSS 1.0 and Atom collection. Upstream and updates: https://github.com/NaturalIntelligence/fast-xml-parser. Ploinky installs it from `package.json` before the agent starts; update the exact version in `package.json` and `package-lock.json` together, then run feed tests. No upstream modifications. Preserve MIT notices. The connector rejects DTD/entity declarations and bounds response size before parsing. Missing imports produce `DEPENDENCY_MISSING` when a feed is parsed. Replacing this parser with another maintained XML implementation is possible without changing the storage contract.

Node.js >=22.13.0 supplies the tool commands, the daemon, tests and SQLite through built-in modules. The agent container image `docker.io/assistos/ploinky-node` (pinned by digest in `manifest.json`) provides Node.js 24 with Git, Python, make and g++ for the RSSHub build. Ploinky's bundled AgentServer serves the MCP tools and the static browser interface; the agent adds no HTTP server. The browser interface is plain HTML, CSS and JavaScript modules served from `web/`, with no framework or bundler; it imports only the router's own `/MCPBrowserClient.js`. The application core needs no PostgreSQL or OpenMagpie. Building RSSHub's native modules uses Python through node-gyp.

## Language detection

`eld` (Efficient Language Detector) 2.1.0, Apache-2.0, by Nito T.M., decides whether a feed entry is English before it is ranked. The operator requested English-only results. A handwritten detector based on common English words misclassified German and Portuguese posts during evaluation, and `franc-min` 6.2.0 (MIT) labeled short English titles as Tagalog, Swedish or German; `eld` classified the same 1,259 collected entries correctly in the inspected samples. It is pure JavaScript with no dependencies and no native code. Scout loads its medium n-gram database (about 2 MB; the package is about 9 MB unpacked) once per process and detects in about 0.07 ms per entry, offline.

- Source and updates: https://github.com/nitotm/efficient-language-detector-js. Installed exactly as 2.1.0 through `package.json` by Ploinky's dependency preparation. No local modifications. Updates require rerunning the language tests and checking that short English titles are still kept.
- License: Apache-2.0; retain the license and notices bundled in the package when redistributing.
- The install step refuses to continue with `SETUP_REQUIRED` while the package is missing. A package that disappears later produces `DEPENDENCY_MISSING` when a cycle first detects a language.
- Removal opportunity: replace `src/app/language.mjs` with another detector exposing the same `detectLanguage(title, text)` contract.

## Inference exception

The user requested a small local embedding model with replaceable models. Neural inference and tokenization need a specialized runtime; implementing ONNX ourselves is impractical. A separate Ollama service adds an environment dependency. We use project-local npm packages instead of vendoring compiled inference binaries.

- Direct package: `@huggingface/transformers` exactly 4.3.1, Apache-2.0, installed in `node_modules` by Ploinky's dependency preparation.
- Source and updates: https://github.com/huggingface/transformers.js. No local upstream changes. Updates require an explicit package version change, refreshed lockfile and real inference tests. The provider version must also change to invalidate stored embeddings.
- Transitive runtime requirements include ONNX Runtime Node and Web, Sharp, Hugging Face Jinja and Tokenizers. Exact resolved versions and integrity hashes are in `package-lock.json`. Package metadata and bundled license/notice files remain in the installed packages. Platform packages not installed on this machine retain their lockfile license and archive location; their notices remain inside those archives.
- License notices remain in installed packages. Apache-2.0 distributions must retain license, copyright and applicable NOTICE files. Native packages may carry additional notices; preserve their bundled files when redistributing.
- Inference, initialization and model download require this package. Missing imports return `DEPENDENCY_MISSING` with installation instructions. Missing model artifacts return `MODEL_UNAVAILABLE`. Only the agent's install step downloads models; tools and cycles never do.
- Removal opportunity: replace `src/embeddings/transformers.mjs` with another provider implementing the documented interface. SQLite and ranking have no third-party runtime dependencies.

Sharp is brought in by the general-purpose Transformers.js runtime even though this agent processes text only. Its prebuilt libvips packages are LGPL-3.0-or-later and bundle libraries under additional licenses, listed in each package's README. Installed libvips packages record their component versions in their bundled `versions.json`. This accepted transitive exception is allowed by the local coding-style policy. There are no library modifications. Keep LGPL notices and corresponding source access when redistributing binaries, and preserve the user's ability to replace/relink the shared libraries; do not repackage them into an inseparable executable. Upstream build/source recipes: https://github.com/lovell/sharp-libvips. Replacing the general-purpose runtime with a text-only runtime would remove Sharp and libvips.

`onnxruntime-node`'s postinstall script downloads CUDA and TensorRT execution-provider libraries on Linux x64 unless it is told to skip them; Scout runs inference on CPU only and never loads them (see npm installation). On Linux x64, the CPU installation without them measured approximately 484 MiB for all npm dependencies. Model caches measured approximately 130 MiB for E5 and 22 MiB for MiniLM. These sizes depend on platform and package versions.

The adapter loads AutoTokenizer and AutoModel directly from the absolute revision-specific cache path for offline inference. Transformers.js 4.3.1's general pipeline/tokenizer discovery can otherwise make metadata requests without propagating the offline/revision options. No upstream code is patched. The smoke test blocks fetch and fails if inference accesses the network.

Verification: `npm test` exercises dependency absence, model absence, invalid input, model/version namespace isolation and persistent SQLite caching. `node scripts/smoke-embeddings.mjs [model]` exercises both real model profiles offline, output shape/norm, a relevance example and rejection of overlong input. `npm install` with the final locked dependency set reported zero known vulnerabilities on 2026-10-08.

## npm installation

Ploinky prepares `node_modules` from `package.json` in its dependency cache before the agent container starts and mounts it read-only at `/code/node_modules` (`NODE_PATH`). The install step checks that every package in `package.json` is present and otherwise stops the start with `SETUP_REQUIRED`, naming the missing packages. `package-lock.json` records the resolved versions and integrity hashes for local development with `npm ci`; Ploinky installs with `--no-package-lock`, so in the agent only the exact direct versions in `package.json` are fixed.

Ploinky writes only the computed `package.json` into its installer container and runs npm with the image's own configuration, so the project `.npmrc` and host environment do not reach that install. `onnxruntime-node` 1.30.0 therefore downloads `Microsoft.ML.OnnxRuntime.Gpu.Linux` 1.30.0 from `api.nuget.org` during dependency preparation: a 236 MB package (about 94 s at 2.5 MB/s) from which it extracts about 273 MB of CUDA and TensorRT libraries, raising `node_modules` from about 514 MB to about 787 MB. This happens once per dependency generation; Ploinky reuses the prepared tree across restarts. The libraries are never loaded at runtime. If NuGet is unreachable, the postinstall script fails and dependency preparation stops the agent start. `.npmrc` (`onnxruntime-node-install=skip`) applies only to local `npm install` or `npm ci` in this folder; `ONNXRUNTIME_NODE_INSTALL=skip` does the same for an install from another directory. A custom agent image setting `ONNXRUNTIME_NODE_INSTALL=skip` would remove the download inside Ploinky.

## Model artifacts

- Default: EmbeddingGemma 300M, ONNX conversion `onnx-community/embeddinggemma-300m-ONNX`, revision `5090578d9565bb06545b4552f76e6bc2c93e4a66`, from https://huggingface.co/google/embeddinggemma-300m. It is distributed under the Gemma Terms of Use (https://ai.google.dev/gemma/terms) and the Gemma Prohibited Use Policy, which are not an OSI open-source license: they permit use, modification and redistribution subject to passing the same use restrictions and terms to recipients. Redistributing the weights requires including those terms. The q8 files (`model_quantized.onnx` and its external data file) are about 309 MB; peak process memory during inference measured about 1.6 GB on Linux x64. It was selected after a labeled comparison with `multilingual-e5-small`, `bge-m3` and `Qwen3-Embedding-0.6B` described in `docs/specs/DS004-embeddings.md`.
- Alternative: `intfloat/multilingual-e5-small`, MIT, https://huggingface.co/intfloat/multilingual-e5-small. ONNX conversion: `Xenova/multilingual-e5-small`, revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`. The conversion identifies its base model but does not bundle a separate LICENSE file. Upstream declares MIT in its model card. Preserve upstream attribution and license metadata when redistributing model artifacts; downloads here are local use.
- Second alternative: `sentence-transformers/all-MiniLM-L6-v2`, Apache-2.0, https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2. ONNX conversion: `Xenova/all-MiniLM-L6-v2`, revision `751bff37182d3f1213fa05d7196b954e230abad9`, Apache-2.0 as declared in its model card. Intended for English.
- Location: `<data-dir>/models`, fetched by the agent's install step when unavailable. Q8 weight files are approximately 309 MB (EmbeddingGemma), 118 MB (E5) and 23 MB (MiniLM), plus tokenizer/configuration assets. npm runtime storage is additional.
- No model training or modifications. Update revisions through `config/embedding-models.json` or a custom configuration; changing the revision produces a separate SQLite embedding namespace.
- Models can be replaced with compatible feature-extraction ONNX models through configuration. Different architectures or inference APIs may require a new provider. Profiles specify dimensions, prefixes, pooling, dtype and token limit; these are model-specific, not inferred from a name.

## External HTTP services

RSSHub runs as a native process inside the agent container, installed by the agent's install step and kept running by the daemon on `127.0.0.1:1200`; it is never exposed outside the container. Reimplementing its site-specific routes inside the agent would duplicate upstream behavior. An existing external endpoint or a custom local command remains a supported alternative.

- RSSHub source: https://github.com/DIYgod/RSSHub, revision `a56c7321107d62a59753c28b2e5f9d27266bcba8`, AGPL-3.0 in package metadata. The install step retains the full checkout, license, pnpm-lock.yaml and dependency notices under `<data-dir>/services/rsshub`. Its frozen lockfile defines direct and transitive package versions. Build output comes from the upstream build command with no source patches. Preserve applicable notices and source-availability obligations when distributing or modifying the service.
- pnpm 10.34.6, MIT, https://github.com/pnpm/pnpm, is installed under `<data-dir>/services/tools` through npm with package install scripts disabled. Its bundled license remains in the installed package. It is needed to honor RSSHub's upstream lockfile; npm alone would resolve a different dependency graph. Updates require changing the installation manifest and verifying a complete build and lifecycle.
- Git, npm, Python, make and g++ are checked before the RSSHub installation. No OS package manager runs. The pinned RSSHub version requires Node 22.22.2+ within v22 or 24.15+ within v24. Missing prerequisites return INSTALL_PREREQUISITE before service checkout creation. Source downloads and builds use bounded subprocesses and write installation logs. Runtime missing executables or failed health probes produce explicit nonzero failures.
- Installation footprint measured on Linux x64 was approximately 961 MiB for the RSSHub checkout/build/dependencies, 41 MiB for the pnpm store and 24 MiB for pnpm tooling, excluding model files and additional caches. Browser downloads are skipped. Routes needing a browser require separately prepared browser dependencies.
- The immutable RSSHub revision and the pnpm version are declared in `config/services/install.json`. Updating them requires reviewing upstream requirements, reconciling the managed checkout explicitly and rerunning installation, native start/stop tests and the built-in RSSHub routes (`/bsky/keyword/...`, `/huggingface/daily-papers`). The install step refuses an unexpected existing checkout revision. A configured external endpoint or custom command can replace the managed installation without changing SQLite or embeddings.


The built-in sites in `config/sites.json` (Reddit, hnrss.org, Mastodon, DEV Community, Medium, Lobsters, Stack Overflow, Product Hunt, Slashdot, lemmy.world, and Bluesky and Hugging Face through RSSHub) are remote services reached over public RSS/Atom feeds without credentials. Their availability, rate limits and terms of use are outside this project; Scout spaces requests, never retries 429 and pauses a host for six hours after 403 or 429. No SDK is installed; built-in fetch supplies requests.

Reading the discussions of results (only for topics with subtopics) uses public, unauthenticated endpoints: the Algolia Hacker News API (`hn.algolia.com`), Reddit's JSON thread view, Lobsters story JSON, Stack Exchange question feeds, the Lemmy, Mastodon and DEV public APIs, the Bluesky public AppView (`public.api.bsky.app`) and Discourse topic JSON; other pages are read as HTML text by built-in code. No SDK or HTML library is installed. The same per-host spacing, 429 handling and six-hour pause after 403 or 429 apply. These services can change or restrict access at any time; a failed read is shown with its error and retried at most three times.

## Documentation browser dependency

The specification viewer and HTML pages import Mermaid 11 ESM from `https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs` for diagrams. Mermaid uses the MIT license; upstream source and notices: https://github.com/mermaid-js/mermaid. The CDN selects a release within major 11, so exact transitive versions are external and not locked by npm in this project. No library modifications or redistribution occur here. This optional browser dependency has no effect on the agent or text documentation; network failure prevents diagram rendering. A static exported diagram can remove the runtime dependency. Update the shared diagram import and test browser rendering together when changing this dependency.
