# Project guidance

## Scope

Promotion Scout is the Ploinky agent `promotionScout` of the AchillesCLI repository (agent id `agent:AchillesCLI/promotionScout`). It performs topic-based RSS/Atom collection from a catalog of sites, local semantic ranking and human review through a static web interface whose every operation is an MCP tool. For results of topics with subtopics it also reads the discussion behind each result and compares it with the subtopics. Do not add SearXNG, open-web search, discovery adapters or credentialed platform APIs. Keep SQLite as the only application database. Do not add OpenMagpie, PostgreSQL, automatic posting, reply generation or keyword fallbacks. Comments generated by earlier versions stay readable in the `generations` table; nothing writes new ones.

## Current Skill Catalog

Update this catalog if the product starts distributing skills. Consumer projects must not place imported-skill specifications or pages in the host `docs/` tree.

## Repository Rules

Update HTML documentation and specifications together when source behavior changes. Keep DS numbering gap-free. All documentation, specifications and comments must be in English. Analyze source, tests, essential commands and user outcomes before modifying the Main Behavior specification or after changes to the product's purpose, public interfaces, architecture, hidden functional consequences or direction. Use evidence-backed accepted behaviors rather than a feature inventory.

Documentation introduces the operator's outcome before implementation, uses concrete verified commands and links specialized terms to `docs/wiki.html`. Headings remain unlinked. Keep prose on logical source lines and allow natural wrapping. State rationale, limitations, assumptions and contract boundaries declaratively inside Core Content; do not depend on a separate decision log.

## Runtime Defaults

Write Node.js ECMAScript modules in `.mjs` files (browser modules in `web/` use `.js`). Prefer built-ins and `node --test`; record justified external dependencies in `dependencies.md`. `docs/specs/DS001-coding-style.md` defines module structure, test organization and size checks. Keep model artifacts, credentials, data directories and `node_modules` out of git.

Use the bundled Ploinky AgentServer; do not add an HTTP server, an extra agent port or Server-Sent Events. The router authenticates every request. User tools in `mcp-config.json` carry no tags (authenticated), run as `node tools/scout.mjs <operation>` with `cwd` `/code`, map one-to-one to `src/agent/operations.mjs`, read their input from the AgentServer stdin payload and print one JSON value; expected failures are returned as `{error: {code, message}}`. Keep input schemas narrow with `additionalProperties: false`. `scout_run_cycle` is the only `internal` tool: an asynchronous task started only by the daemon.

`/code` is read-only inside the container. Everything the agent writes lives in `SCOUT_DATA_DIR` (`/data`, the volume `.data/promotionScout`), resolved by `src/app/paths.mjs`. The install step (`scripts/install.sh`, `src/app/bootstrap.mjs`) runs before every agent start and is the only place that downloads the model or installs RSSHub; Ploinky installs the npm dependencies from `package.json`, and the install step fails with `SETUP_REQUIRED` when one is missing. Completed install steps must stay quick no-ops.

`scripts/startAgent.sh` starts AgentServer and the daemon (`src/agent/main.mjs`) and supervises both. The daemon holds the lifecycle lock of the data directory, keeps RSSHub running, writes its heartbeat and starts each due cycle as a `scout_run_cycle` task through the router with Ploinky's `AgentMcpClient`. Monitoring state lives only in SQLite settings (`src/app/control.mjs`): Start makes the first cycle due immediately, later cycles are due one interval after the previous start, and monitoring resumes after restarts until Stop. Stop clears the flag; the cycle aborts itself and the daemon cancels the task only if it does not. Never keep monitoring state in a process.

Keep embedding inference behind `src/embeddings/index.mjs`. Model profiles own token prefixes, pooling, dimensions, dtype, immutable revision, token limits and the relevance threshold; the default is EmbeddingGemma 300M with threshold 0.25. Change a threshold only after calibration on labeled posts. Inference runs in a worker thread of the cycle task and only during a cycle. Rank only English entries; language detection stays local (`eld`) and must keep short titles. Any change to vector semantics must invalidate the embedding namespace, including provider implementation changes. A missing model must fail the cycle explicitly; inference failures must fail their run without substitute scores.

Run `npm test` after behavioral changes. For inference/provider changes, also run `node scripts/smoke-embeddings.mjs` after downloading the default model. Run the Ploinky validator (`node ../.agents/skills/manage-ploinky-agents/scripts/validate-ploinky-agent.mjs --agent-dir .`) after manifest or MCP changes. Do not claim mock tests validate model quality. Run `bash fileSizesCheck.sh` and check documentation links and HTTP-loaded shared assets after documentation changes.

The SQLite schema has no migrations or legacy compatibility; a different schema version is rejected. Keep the monitoring interval to the offered choices (1, 2, 4, 6, 8, 12, 24, 48 or 168 hours) and feed polling at one hour, including failed attempts; preserve explicit errors during cooldowns. Never retry a 429; pause a host for six hours after a 403 or 429, and keep per-host request spacing. Built-in sites live in `config/sites.json`; automated tests must not contact them. Record every cycle as a run and mark a passing URL new only the first time it is found.

Collection must ingest only RSS/Atom entries (RSS 2.0, RSS 1.0, Atom), read directly or through RSSHub routes. HTML may be inspected to find a same-origin feed link when a site is added, and discussion pages or public discussion APIs may be read only for results of topics with subtopics, through the per-host gate (`src/app/polite.mjs`), as `docs/specs/DS008-discussions.md` defines. Unknown tags are explicit skips. Feed provenance must match the source, item and current content hash before ranking or display.

## Key Paths

- `manifest.json`, `mcp-config.json`: Ploinky runtime contract and MCP tools.
- `scripts/install.sh`, `scripts/install.mjs`: the install step; `scripts/startAgent.sh`: AgentServer plus daemon supervision.
- `src/agent/`: daemon (`main.mjs`, `daemon.mjs`), cycle task (`cycle.mjs`), tool operations (`operations.mjs`) and the shared context.
- `tools/`: MCP tool entries (`scout.mjs` for user tools, `run-cycle.mjs` for the cycle task).
- `src/app/`: topics, subtopics, site catalog and feed selection, discussion reading and scoring, SQLite storage, monitoring control, the cycle, read-only views, install and RSSHub process management.
- `config/sites.json`: built-in site catalog; `config/embedding-models.json`: model catalog; `config/services/`: RSSHub install manifest.
- `web/` and `index.html`: static browser interface (MCP client in `agent.js`) and the redirect to it.
- `IDE-plugins/scout-tool-button/`: Explorer toolbar button that opens `/promotionScout/web/` in Explorer's expanded modal.
- `src/providers/`: HTTP client, RSS/Atom parsing, feed resolution and discussion readers (`threads.mjs`).
- `src/embeddings/`: model profiles, runtime adapter and vector cache.
- `test/` and `scripts/`: automated behavior checks and the real-model smoke check.
- `docs/index.html`, `docs/wiki.html`, `docs/specs/`: documentation entry, terminology and authoritative contracts.
