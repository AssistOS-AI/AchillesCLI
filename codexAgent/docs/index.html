Codex Agent

Codex Agent packages the official OpenAI Codex CLI as a Ploinky worker. It supports direct interactive use and asynchronous coding tasks that preserve a Codex thread for later continuation.

Use Codex Agent

For direct interactive use, start the provider CLI through Ploinky:

ploinky cli codexAgent

For a background task owned by AchillesCLI, request Codex by name in WebChat or call the launcher skill:

Ask Codex to add regression tests for the parser.
/exec launch-codex Add regression tests for the parser.

The launcher activates the manual-start worker when required, creates an asynchronous task, and returns Task started.. AchillesCLI can then inspect, stop, or continue the task:

/tasks
/task view <task-id>
/task continue <task-id> Fix the remaining failing test.
/task stop <task-id>

Task lifecycle

Execution behavior

Initial tasks run Codex non-interactively with JSON event output, a workspace-write sandbox, and approval prompts disabled. The wrapper forwards completed agent messages and command output to the Ploinky task log while keeping Codex control events and reasoning records out of the visible stream. The last bounded agent message becomes the structured final result.

When Codex reports a thread, the worker stores the thread identifier and original project directory behind a random opaque continuation handle. AchillesCLI stores only that handle and the fixed worker identity. A continued turn starts a new remote execution while preserving the same AchillesCLI task identifier.

Model and authentication behavior

The AchillesCLI launcher does not forward the model selected for the main conversation. A direct internal initial call may supply a Codex model override. Continuation does not persist or replay the initial model: it uses an explicit task-specific override when one is supplied and otherwise uses the Codex configuration active when the new turn starts. In generated-local Ploinky mode, the worker uses the scoped Soul Gateway provider contract. Outside that mode, Codex uses its own persistent login or supported provider environment.

The task-session control surface supports typed authentication operations without exposing provider session records to WebChat. The agent home persists the installed CLI, provider authentication, configuration, and Codex threads across worker recreation.

Security and boundaries

The provider runs in the supplied project directory under Codex's workspace-write policy and the outer Ploinky runtime boundary. Commands that require writes outside the workspace fail without an interactive approval path. The continuation store rejects invalid handles and unsafe symlinked storage. Provider thread identifiers, filesystem paths, prompts, and credentials do not appear in the generic continuation descriptor.

The agent contracts are indexed in the Codex Agent specification matrix. Task continuation and authentication are defined in DS004.
