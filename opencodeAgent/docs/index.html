OpenCode Agent

OpenCode Agent packages the OpenCode CLI as a manual-start Ploinky worker. It supports resumable asynchronous coding tasks and also exposes OpenAI-compatible model discovery and chat-completions endpoints for Ploinky routing.

Use OpenCode Agent

Start the native OpenCode CLI directly through Ploinky:

ploinky cli opencodeAgent

For background work managed by AchillesCLI, request OpenCode by name or execute the launcher skill:

Ask OpenCode to refactor the configuration loader.
/exec launch-opencode Refactor the configuration loader.

AchillesCLI releases the active conversation as soon as the asynchronous task starts. The standard /tasks and /task commands show logs, stop a running execution, or continue the provider session with a new prompt.

Task lifecycle

Execution and continuation

Initial tasks run OpenCode in its formatted-output mode with automatic operation approval. The installed permission policy allows normal actions but denies external-directory access, and the independent Bubblewrap namespace limits writable project access to the canonical task directory. Provider stdout and stderr flow into the task log without wrapper prefixes or synthetic lifecycle messages.

After execution, the wrapper resolves the new OpenCode session and exports its messages to select the last assistant text as the structured result. Session lookup and export data do not enter the visible task log. The session identifier and original directory are stored behind a random opaque continuation handle. A continued turn reuses that session while AchillesCLI preserves the same local task identifier.

Models and Ploinky endpoints

The AchillesCLI launcher does not impose the main conversation's model on OpenCode. Before continuation, the worker reads OpenCode's recent provider, model, and non-default variant from its persistent state; missing state falls back to native resume behavior. The task-session control surface supports typed provider authentication flows without exposing private provider state to the browser.

The models endpoint publishes OpenCode's provider/model catalog to Ploinky with coding-agent metadata. The non-streaming chat-completions endpoint converts OpenAI-style messages into one OpenCode prompt and runs it in Ploinky's effective WORKSPACE_PATH. These provider endpoints are separate from resumable asynchronous MCP tasks.

Security and persistence

Every task, continuation, session lookup, and session export runs inside the task-local Bubblewrap boundary. The namespace exposes the selected project directory as the only writable workspace bind, limits separate writes to required OpenCode state directories, shares networking for provider calls, and filters raw Ploinky and provider credentials from the task environment. The worker remains unready if the nested sandbox cannot start.

The Ploinky agent home persists the installed OpenCode CLI, authentication, recent-model choices, provider sessions, and opaque continuation records. The full contract is recorded in DS012 OpenCode launcher delegation.
