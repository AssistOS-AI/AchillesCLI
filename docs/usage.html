AchillesCLI Command Reference

AchillesCLI accepts startup options and natural-language prompts from the shell, then exposes slash commands for direct control inside an interactive session. Every command operates inside the selected workspace boundary.

Start and configure

achilles-cli

Starts an interactive REPL in the current directory. A prompt runs one request and exits. --dir selects another workspace, and repeatable --skill-root options add skill roots for this process.

Usage:

achilles-cli [options] [prompt]

Examples:

achilles-cli
achilles-cli --dir /path/to/project
achilles-cli "explain the authentication flow"
achilles-cli --skill-root /path/to/shared-skills

achilles-cli --permissions

Selects the initial Bash permission mode. ask-for-approval requests approval for each new command; full-access skips prompts without widening the workspace sandbox.

Usage:

achilles-cli --permissions <ask-for-approval|full-access>

Examples:

achilles-cli --permissions ask-for-approval
achilles-cli --permissions full-access --dir /path/to/project

achilles-cli --fast and --deep

Selects the fast or deep LLM tier alias for the process.

Usage and examples:

achilles-cli --fast "list the files changed in this branch"
achilles-cli --deep "review the repository architecture"

achilles-cli --ui

Selects claude-code, the default interactive presentation, or the simpler minimal terminal interface.

Usage:

achilles-cli --ui <claude-code|minimal>

Examples:

achilles-cli --ui minimal
achilles-cli --ui-claude-code

achilles-cli --help and --version

Prints process-level help or the CLI version without starting an agent session.

Usage and examples:

achilles-cli --help
achilles-cli --version

Help and navigation

/help

Opens the help picker or prints help for a named topic.

Usage: /help [topic]

Examples:

/help
/help commands
/help testing

/history

Shows history, limits it to the latest entries, searches for text, or clears it. history and hist also work without the slash.

Usage: /history [clear|<n>|<query>]

Examples:

/history
/history 20
/history authentication
/history clear

/reload

Refreshes registered skills from disk so edits become available during the session. reload also works without the slash.

Example:

/reload

/exit and /quit

Ends the interactive REPL. /q is an additional alias.

Examples:

/exit
/quit

Skill discovery and files

/list skills

Lists registered user skills. Adding all includes built-in skills. The quick commands list, ls, list all, and ls -a provide the same common listings.

Usage: /list skills [all]

Examples:

/list skills
/list skills all

/read

Reads the descriptor file for one registered skill.

Usage: /read <skill-name>

Example:

/read inventory

/write

Creates or updates a skill descriptor. The optional type selects the descriptor family for a new skill.

Usage: /write <skill-name> [type]

Examples:

/write inventory cskill
/write inventory

/delete and /remove skill

Deletes the directory for a named skill. Both forms run the same deletion behavior.

Usage:

/delete <skill-name>
/remove skill <skill-name>

Example:

/delete obsolete-skill

/template

Returns the blank descriptor template for a supported skill type.

Usage: /template <type>

Examples:

/template cskill
/template oskill

/validate

Validates a skill descriptor against the schema for its registered type.

Usage: /validate <skill-name>

Example:

/validate inventory

/specs

Reads Markdown files from a skill's specs/ directory.

Usage: /specs <skill-name>

Example:

/specs inventory

/specs-write

Creates or updates specification content for a skill.

Usage: /specs-write <skill-name> [content]

Examples:

/specs-write inventory
/specs-write inventory Require every item identifier to be unique.

/update

Updates one named section of a skill descriptor while preserving the rest of the file.

Usage: /update <skill-name> <section>

Example:

/update inventory Description

/scaffold

Creates a documentation-oriented skill structure with SKILL.md, resources, and scripts.

Usage: /scaffold <doc-type> <skill-name>

Example:

/scaffold research product-research

/skill

Enables or disables one registered workspace skill. Disabled skills remain available to the enable command.

Usage: /skill <enable|disable> <skill-name>

Examples:

/skill disable experimental-search
/skill enable experimental-search

/skills

Lists workspace skill state or changes every registered skill below a relative workspace directory.

Usage:

/skills
/skills <enable|disable> <relative-directory>

Examples:

/skills
/skills disable skills/experimental
/skills enable skills/experimental

Build and test

/build

Builds skills that have pending generated-code work.

Example:

/build

/generate

Generates runtime modules for a supported tskill, database-table skill, or cskill.

Usage: /generate <skill-name>

Example:

/generate inventory

/write-tests

Generates a test file for one skill.

Usage: /write-tests <skill-name>

Example:

/write-tests inventory

/test

Runs the test-code skill for one named skill. Without a name, AchillesCLI opens a picker.

Usage: /test [skill-name]

Examples:

/test
/test inventory

/run-tests

Runs discovered .tests.mjs files for one skill or all skills. Without an argument, AchillesCLI opens a picker.

Usage: /run-tests [skill-name|all]

Examples:

/run-tests inventory
/run-tests all

/refine

Uses test results to improve a named skill iteratively until the configured stopping condition.

Usage: /refine <skill-name>

Example:

/refine inventory

/exec

Executes any enabled registered skill. Text after the skill name becomes its input.

Usage: /exec <skill-name> [input]

Examples:

/exec web-search latest Node.js release notes
/exec inventory

Repositories

/add repo

Clones a Git repository into the managed repository area. The optional name overrides the URL-derived name.

Usage: /add repo <URL> [name]

Example:

/add repo https://github.com/AssistOS-AI/example-skills.git example-skills

/list repos

Lists repositories cloned through AchillesCLI.

Example:

/list repos

/update repos

Pulls updates for every cloned repository.

Example:

/update repos

/remove repo

Removes one cloned repository by its managed name.

Usage: /remove repo <name>

Example:

/remove repo example-skills

Runtime settings

/tier

Shows available LLM tiers or selects a tier alias. Selecting a tier clears an explicit model selection.

Usage: /tier [name]

Examples:

/tier
/tier fast
/tier deep

/model

Shows available models or stores one exact model selection for the workspace. Names come from the authenticated Soul Gateway catalog.

Usage: /model [model-name]

Examples:

/model
/model provider/model-name

/permissions

Shows or changes the persistent Bash permission mode for the current workspace.

Usage: /permissions [ask-for-approval|full-access]

Examples:

/permissions
/permissions ask-for-approval
/permissions full-access

/raw

Toggles terminal Markdown rendering for the active session.

Example:

/raw

Sessions and tasks

These commands are summarized here as part of the command reference. See Sessions and Asynchronous Tasks for the lifecycle, persistence model, delegation boundary, and WebChat workflow.

/session

Opens the session picker. new creates a durable conversation; resume selects a saved session.

Usage:

/session
/session new
/session resume <session-id>

Examples:

/session new
/session resume <session-id-from-the-picker>

/tasks

Shows workspace-local background task status and bounded final log tails. A number limits the results; all returns every stored summary.

Usage: /tasks [count|all]

Examples:

/tasks
/tasks 10
/tasks all

/task view

Shows stored metadata and the latest stored log lines for one task.

Usage: /task view <task-id>

Example:

/task view task-7

/task continue

Continues a compatible terminal task with a new prompt while retaining its local identifier.

Usage: /task continue <task-id> <prompt>

Example:

/task continue task-7 add tests for the new parser

/task stop

Requests cancellation of a queued or running task.

Usage: /task stop <task-id>

Example:

/task stop task-7

/task model

Shows model choices for a continuable task or selects its execution model.

Usage: /task model <task-id> [model-key]

Examples:

/task model task-7
/task model task-7 provider/model-name

/task login

Starts a provider connection flow inside the task agent. Optional arguments select a provider and login method.

Usage: /task login <task-id> [provider] [method]

Examples:

/task login task-7
/task login task-7 codex device-code

Natural-language requests

Text that does not match a quick or slash command is sent to the local agent for planning and execution. Use natural language for work requiring several tools or decisions.

Examples:

explain how requests reach the Soul Gateway
create a cskill that summarizes JSON files
run the relevant tests and fix any failures
