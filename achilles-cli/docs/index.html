AchillesCLI Documentation

What AchillesCLI is

AchillesCLI is primarily a local command-line agent that runs on your system and works inside the directory you select. It gives you a conversational CLI for working with code and reusable agent skills: start it in a project directory, submit a one-shot prompt or open an interactive REPL, and receive results without giving the agent unrestricted access to the rest of the system. The selected directory becomes the session's filesystem boundary.

Ploinky integration adds managed startup, agent-to-agent delegation, and a dedicated Ploinky WebChat interface. In Explorer, the directory action is labeled Open Copilot here and opens WebChat with that folder as its workspace context. These integration surfaces use the same AchillesCLI skill discovery, model routing, workspace confinement, conversation, and task contracts as the local CLI.

Quick Setup

After cloning the repository, install the prerequisites and package-local npm dependencies, expose the selected development AchillesAgentLib checkout through the standard package link, then add the AchillesCLI wrapper to Bash's persistent PATH. A Ploinky launch creates this link from its one workspace-selected AgentLib source automatically.

cd AchillesCLI/achilles-cli
sudo sh scripts/installPrerequisites.sh
npm install
mkdir -p node_modules
ln -s /absolute/path/to/achillesAgentLib node_modules/achillesAgentLib
echo "export PATH=\"\$PATH:$PWD/bin\"" >> ~/.bashrc
source ~/.bashrc
cd /path/to/your/project
achilles-cli

The PATH command stores the absolute path to AchillesCLI/achilles-cli/bin, allowing achilles-cli to run from any working directory. Configure the Soul Gateway environment separately when the selected model provider requires it.

What AchillesCLI can do

AchillesCLI can inspect and modify files in the selected project, execute approved local commands, answer one-shot prompts, and maintain multiple resumable conversations in the same project folder. Its built-in skill commands discover, read, create, update, delete, validate, generate, execute, test, and iteratively refine skill definitions. Workspace controls enable or disable registered skills, select a model, manage permission mode, resume conversations, and inspect persistent background tasks.

When integrated with Ploinky, AchillesCLI can delegate coding work asynchronously to Codex, OpenCode, and PI. It can also list the workspace's RoboTeam robots through internal MCP and start a visible Desktop or Browser task in the selected workspace. WebChat shows the growing task log inside a collapsible chat card. A visible task also returns an authenticated Selkies link that opens in the right panel, so the user can read ALA messages and watch the robot work at the same time. The task card can stop ALA while preserving the workstation for manual control, then resume the exact interrupted request after RoboTeam supplies its continuation handle. RoboTeam uses the same native Ploinky task contract as provider workers, so AchillesCLI's background-task journal receives intermediate ALA messages, continuation turns, and the terminal result. See Sessions and Asynchronous Tasks for the complete workflow.

The runtime combines a trusted command broker with a sandboxed AchillesAgentLib MainAgent. All model calls pass through LLMAgent, and Bash approval never expands the selected workspace boundary.

Repository structure

achilles-cli/src/cli.mjs is the trusted entry point; achilles-cli/src/index.mjs is the sandboxed runtime; achilles-cli/src/skills/ contains the product's built-in skills; and achilles-cli/src/schemas/ defines descriptor-family validation. Root tests/ exercise integration behavior, while achilles-cli/tests/ cover package-local runtime contracts. The manifests in GPTResearcher/, opencodeAgent/, piAgent/, and codexAgent/ describe optional Ploinky workers used by launcher skills. The sibling roboTeamAgent/ component is an independent Ploinky profile and desktop manager documented from the repository's agent suite hub.
