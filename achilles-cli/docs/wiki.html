AchillesCLI Documentation

This page is the canonical source for project-specific terms used by the HTML documentation and design specifications.

AchillesCLI
AchillesCLI is primarily the local, skill-oriented command-line agent implemented under achilles-cli/. A user runs it on their system inside a selected project directory to submit prompts, work with files, manage Achilles skill definitions, and control delegated tasks. Ploinky can also host the agent, route work to it, and expose its dedicated WebChat interface. The trusted entry point establishes the workspace and Bash approval authority; the sandboxed entry point owns agent reasoning, skills, sessions, and output. AchillesCLI depends on AchillesAgentLib for agent primitives and uses Ploinky for managed deployment and inter-agent routing, while retaining ownership of its conversation and task records.
AchillesAgentLib
AchillesAgentLib is the authorized shared runtime dependency that provides MainAgent, LLMAgent, skill discovery, planning, and execution primitives. AchillesCLI configures and extends those primitives through repository entry points and runtime adapters. The library is resolved through the Ploinky or development runtime rather than copied into this repository, and AchillesCLI must route model calls through its LLMAgent abstraction.
MainAgent
MainAgent is the AchillesAgentLib agent instance that interprets prompts, selects skills, records exact-call approvals, and composes final answers. AchillesCLI creates it in src/index.mjs inside the Bubblewrap workspace sandbox. It may start local Bash children only through LocalBashExecutor after the Broker-backed supervisor authorizes them. It does not own the trusted permission-mode control capability.
LLMAgent
LLMAgent is the only authorized model-invocation abstraction for AchillesCLI. Runtime configuration, environment variables, workspace tier selection, or an explicit Soul Gateway model configure its behavior. Repository modules may decorate its invoker for Soul Gateway routing, but they must not bypass it with direct vendor HTTP requests. Soul Gateway remains responsible for validating an effective model identifier and selecting a provider.
AchillesBroker
AchillesBroker is the trusted process-side object created by src/cli.mjs before the MainAgent sandbox starts. It owns the authoritative Bash permission mode, terminal or WebChat approval interactions, the private control token, and sandbox-child lifecycle. It accepts structured authorization requests but exposes no Bash execution operation; approved commands are executed by LocalBashExecutor inside the sandbox.
Bubblewrap
Bubblewrap, invoked as bwrap, creates the Linux mount namespace that confines the sandboxed AchillesCLI process. The namespace exposes the selected workspace as writable and runtime dependencies as controlled read-only mounts, with isolated temporary storage and a private or safe fallback /proc. Bash approvals never alter these mounts. When platform prerequisites cannot establish the required boundary, the trusted launcher fails instead of starting an unconstrained MainAgent.
Workspace boundary
The workspace boundary is the real directory selected from the invocation directory or --dir. It determines the files visible and writable to the MainAgent and its Bash child processes, the location of .achilles-cli settings and persistence, and the scope of workspace skill discovery. Permission decisions affect whether a Bash call starts; they do not add sibling projects, the user's complete home directory, or other host paths to this boundary.
Permission mode
The permission mode is the Broker-owned choice between ask-for-approval and full-access. The first requires a decision for a new exact Bash tool call, while the second starts Bash calls without the approval interaction. A validated value is stored per workspace in .achilles-cli/settings.json, and a startup flag can override it for one process. Both modes retain the same Bubblewrap filesystem restriction, and only the trusted control channel may change the live Broker value.
Skill
A skill is a registered Achilles operation described by a family-specific Markdown descriptor and, when needed, local executable modules, tests, or sidecar specifications. Users invoke skills through natural-language planning or slash commands. AchillesCLI distributes built-ins under achilles-cli/src/skills/, discovers workspace and additional roots, validates descriptor families, and applies persistent enablement controls. A skill's portable artifacts remain in its directory rather than depending on a shared generated-code tree.
REPL
The read-evaluate-print loop is AchillesCLI's interactive terminal mode, selected when the sandboxed runtime has a TTY and receives no one-shot prompt. REPLSession reads natural language and slash commands, manages history, supports command selection and ESC cancellation, and renders results through the configured UI provider. Conversation-session persistence is separate from terminal command history, and exiting the REPL ends the process without changing the workspace boundary.
WebChat
WebChat is the non-TTY transport in which AchillesCLI reads structured Ploinky envelopes from standard input and writes answers plus hidden UI-control envelopes to standard output. It presents approvals, sessions, task events, runtime model state, and workspace-file snapshots. AchillesCLI remains the owner of conversation and task persistence; WebChat carries and displays the state but does not store authoritative records or widen local filesystem access.
Background task
A background task is an asynchronous execution delegated through a launcher skill and AgentServer to another Ploinky agent. AchillesCLI assigns a stable local identifier, stores metadata in an append-only journal, stores output in task logs, polls the remote execution, and supports view, stop, and compatible continuation operations. A continuation may create a new remote task and opaque provider handle while retaining the local task identifier and ordered log.
Agentic Knowledge Unit
An Agentic Knowledge Unit, abbreviated AKU, is a deterministic AchillesAgentLib memory record used by AchillesCLI's Copilot behavior. AchillesCLI interprets prompt intent, chooses relevant units, invokes the library API, and supplies compact context to the agent loop. AchillesAgentLib owns storage, search, locking, recovery, and the data model; AchillesCLI does not redefine those rules and must not treat provider-result similarity as sufficient authority to create durable memory.
Soul Gateway
Soul Gateway is the authenticated local routing service used by AchillesCLI for model discovery and invocation. The /model command searches its catalog and stores the chosen identifier, while the runtime forwards that identifier through an LLMAgent invoker configured with the soul_gateway provider key. The local catalog supports selection and display but is not an execution allowlist; Soul Gateway validates and routes each request.
AgentServer
AgentServer is the Ploinky-facing interface that exposes agent tools, asynchronous task operations, and AchillesCLI's MCP skill catalog. Launcher skills use it through authenticated router calls to start and follow external work. AchillesCLI stores local task state and forwards request-bound assertions where required; AgentServer owns the target operation and remote status, not the user's local conversation records.
