AchillesCLI Documentation

The built-in catalog under achilles-cli/src/skills/ supplies the concrete operations used by slash commands and natural-language planning.

Skill artifacts and discovery

Each built-in directory contains a descriptor such as cskill.md or oskill.md and, when execution is required, a local src/index.mjs or orchestrator module. Launcher skills may also carry a specs/ contract. AchillesCLI combines this built-in root with registered workspace roots and repeatable --skill-root values, then applies persisted workspace enablement before execution.

Repositories added with /add repo live under <workspace>/.data/achilles-cli/repos/. AchillesCLI validates and registers this managed root at startup and on explicit catalog reload, so its skills remain discoverable when --dir selects a nested project. Reload adds new skills, removes deleted skills and aliases, and preserves disabled canonical names. It does not scan other agents' private state or AKU storage, and it does not change the selected project or its sandbox boundary.

Schema families

achilles-cli/src/schemas/skillSchemas.mjs recognizes the project's code, orchestrator, MCP, table, and dynamic-code descriptor families. Validation checks the required and optional sections for the detected family. Generated modules and tests remain inside the skill directory so a copied skill carries its implementation and verification artifacts with it.

Enable or disable workspace skills

AchillesCLI keeps skill state per workspace. Disabling a skill prevents normal execution and removes it from executable command suggestions, but does not delete the skill. It remains registered so it can be enabled again later.

Change one skill

Use the canonical skill name when only one skill should change.

/skill disable experimental-search
/skill enable experimental-search

Change a directory of skills

Use a directory path relative to the current workspace to change every registered skill below that directory. The operation includes registered descendants in nested directories.

/skills disable skills/experimental
/skills enable skills/experimental

Run /skills without arguments to inspect the registered catalog and its current state.

CLI and WebChat

The same persistent state applies in both interfaces. In the CLI, enter the slash commands with an exact skill name or relative directory. Ploinky WebChat exposes the skill catalog and state as interface controls, which makes selecting and toggling an individual skill or a whole skill directory more convenient.

Execution boundary

The skill descriptor defines the operation presented to the planner. AchillesAgentLib performs discovery and agent-loop execution, while AchillesCLI provides built-in handlers, workspace state, UI adapters, and the Bash security boundary. Product requirements for discovery and execution are authoritative in DS007 and schema contracts in DS008.
